# Ответ на запрос код-ревью

Этот документ описывает что должен ответить код ревьюер на запрос, рекомендуется проставлять галочки.

---
## Когда подавать ответ на запрос:

- Всегда, если взялся за ревью кода.

> **Важно:** Ни один код не попадает в `develop` или `main` без прохождения код-ревью.
---
## Шаблон ответа:
Скопируй этот шаблон и отправь заполненный файл \*.md в ответном сообщении и отметь того чей код ревьюил.

```markdown
# Change Request: [Краткое название]

## Общая информация
 Ревьюер : @username 
 Дата : ГГГГ-ММ-ДД 
 Чей запрос: @username
 Категория : Код / Геймдизайн / Архитектура / Контент / Git / Другое 
 Связанные задачи : #ISSUE-123, #PR-45 

---

# Чек-лист для ревьюера
Пожалуйста, проверь следующие пункты:
- [ ] Код компилируется без ошибок и варнингов.
- [ ] Код соответствует `CODING_CONVENTIONS.md` (нейминг, форматирование).
- [ ] Сложные участки снабжены комментариями.
- [ ] Нет `Debug.Log()` в продакшен-коде (кроме отладочных сборок).
- [ ] Словари/списки инициализированы (нет `NullReferenceException`).
- [ ] Методы не длиннее 30-40 строк (где возможно — разбиты).
- [ ] Отсутствуют дублирования (DRY).
- [ ] Изменения не нарушают работу смежных систем.
- [ ] Нет нарушений слоёв (например, UI не вызывает геймплейную логику напрямую).
- [ ] Нет `Instantiate()` и `Destroy()` в `Update()` — используется Object Pool.
- [ ] Нет `Find()` и `GetComponent<>()` в циклах.
- [ ] Нет создания мусора (аллокаций) в `Update()`.
- [ ] Магические числа вынесены в константы или `ScriptableObject`.
- [ ] Есть комментарии к неочевидной логике.
- [ ] Обработаны краевые случаи (null, пустые списки, выход за границы массива).
- [ ] Есть тесты (если применимо).
---
## 📝 Заключение ревьюера
_Заполняется ревьюером после проверки._
- [ ] **Принято** — можно мержить.
- [ ] **Принято с замечаниями** — можно мержить, но замечания нужно учесть в следующих PR.
- [ ] **Отклонено** — требует доработок (комментарии ниже).
```
